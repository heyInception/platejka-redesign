# Hero с калькулятором: дизайн реализации

## Цель

Завершить Hero страницы переводов в Китай в текущем Gulp-проекте по desktop- и mobile-макетам Figma. Блок должен включать рабочий калькулятор, выразительную GSAP-анимацию, доступную модалку-заглушку и контракт данных, который впоследствии переносится в WordPress/ACF без переписывания клиентской логики.

WordPress-тема `platejka-pagespeed` используется только как источник бизнес-логики и контракта данных. В рамках этой задачи тема не изменяется.

## Источники истины

- Desktop: Figma node `2070:1298`.
- Mobile: Figma node `4045:4004`.
- Формула и формат сообщений: `cross-blocks.js` из действующей WordPress-темы.
- Компонентные стили и токены: текущий Gulp-проект.

Демонстрационные числа в Figma не являются бизнес-данными. При расхождении расчёт выполняется по рабочему JavaScript-контракту.

## Структура и семантика

Hero остаётся самостоятельной секцией страницы с одним `h1`. Заголовок получает две контентные части:

- `title_primary` — основной цвет;
- `title_secondary` — `var(--text-overlay-secondary)`.

В статическом шаблоне части представлены двумя вложенными элементами внутри одного `h1`. При переносе в ACF они становятся двумя текстовыми полями и безопасно выводятся через PHP без HTML, введённого редактором.

Калькулятор оформляется как `form`, хотя не отправляет данные по сети. Валюты реализуются нативными кнопками с состоянием `aria-pressed`, сумма — числовым `input` с явным `label`, результаты — через `output`. Декоративные изображения получают пустой `alt`; содержательные ссылки и действия сохраняют корректные типы элементов.

Модальное окно реализуется нативным `dialog`. Его могут открывать CTA калькулятора и существующие кнопки «Связаться». На первом этапе внутри находятся заголовок, пояснение, сводка расчёта и кнопка закрытия; полей и отправки нет.

## Данные и расчёт

Корневой элемент калькулятора хранит курсы в JSON-атрибуте `data-currency-rates`. Начальный статический набор содержит CNY и USD. При WordPress-интеграции тот же атрибут формируется PHP из серверных курсов и ACF-настроек.

Начальное состояние:

- валюта — CNY;
- сумма — 100000;
- результат рассчитан сразу после инициализации.

Формула сохраняется из рабочего `cross-blocks.js`:

1. При сумме меньше 3000 комиссия в валюте равна 275.
2. При сумме от 3000 комиссия равна 0,5% суммы.
3. Официальный курс — значение из `data-currency-rates`.
4. Наш курс конвертации — официальный курс × 1,01.
5. Основной платёж — сумма × официальный курс × 1,01.
6. Комиссия в рублях — комиссия в валюте × официальный курс × 1,01.
7. Итог — основной платёж плюс комиссия.
8. Денежные значения округляются до двух знаков и форматируются в локали `ru-RU`.

Пересчёт выполняется при вводе и переключении валюты. CTA проверяет положительную сумму, обновляет расчёт и открывает модальное окно со сводкой. Никакие Telegram- или серверные вызовы в этой задаче не выполняются.

## Адаптивная компоновка

Desktop повторяет Figma: слева цветной Hero и три карточки доверия, справа калькулятор с верхним регистрационным баннером.

Mobile повторяет порядок макета:

1. цветной Hero;
2. калькулятор;
3. регистрационный баннер под калькулятором;
4. три компактные карточки доверия.

Desktop- и mobile-состояния используют одну разметку; порядок меняется CSS-свойством `order` и сеткой/флекс-контекстом. Отдельная дублирующая мобильная разметка не создаётся.

## Изображения и будущий ACF

Основное изображение и blur-изображение передаются через inline CSS-переменные:

```html
style="--hero-image: url(...); --hero-blur: url(...)"
```

SCSS использует `--hero-image` для основного декоративного слоя, а `--hero-blur` — для отдельного слоя размытия. При переносе в WordPress значения формируются из двух ACF image-полей с экранированием URL.

Предлагаемый будущий набор ACF-полей:

- badge;
- title_primary;
- title_secondary;
- description;
- metrics repeater: value, label;
- supporting_note;
- hero_image;
- hero_blur;
- trust_cards repeater;
- calculator_title;
- currencies;
- registry_banner;
- calculator_note;
- calculator_button_label.

## GSAP-анимация

Intro-анимация запускается после пользовательского события `platejka:ready`, которое отправляет прелоадер после завершения. Если прелоадера нет, Hero запускается без ожидания.

Последовательность:

1. контейнер раскрывается через `clip-path`;
2. цветной фон и декоративное изображение входят с разной глубиной;
3. badge, две части заголовка, описание, метрики и примечание появляются каскадом;
4. калькулятор и карточки доверия мягко поднимаются с небольшим stagger;
5. после intro остаётся медленное «дыхание» фонового/blur-слоя;
6. на устройствах с точным указателем добавляется ограниченный параллакс изображения от позиции курсора.

На мобильных курсорный параллакс отключён, intro короче. При `prefers-reduced-motion: reduce` анимация не запускается, а элементы сразу получают финальное видимое состояние. GSAP-контексты, media-query listeners и pointer listeners очищаются корректно.

## Модальное окно

Открытие выполняется через единый контроллер, который поддерживает существующий атрибут `data-graph-path="call"`, но не зависит от библиотеки `graph-modal`. Для `dialog` предусмотрены:

- закрытие кнопкой;
- закрытие по Escape средствами браузера;
- закрытие кликом по backdrop;
- возврат фокуса на элемент, открывший окно;
- блокировка повторного открытия;
- сводка выбранной валюты, суммы, комиссии и итога.

## Файлы и границы изменений

Планируемые изменения в Gulp-проекте:

- `src/partials/hero.html` — завершённая семантическая разметка Hero;
- новый partial модального окна либо включение `dialog` в Hero, если он используется только здесь;
- `src/scss/components/_hero.scss` — desktop/mobile стили;
- при необходимости отдельный SCSS-компонент диалога;
- `src/js/components/hero.js` — калькулятор, dialog-контроллер и GSAP-анимация;
- `src/js/components/preloader.js` — отправка `platejka:ready`;
- `src/js/_components.js` — импорт Hero;
- тесты Hero/калькулятора и обновление документации при необходимости.

WordPress-тема, API курсов и ACF-конфигурация не изменяются.

## Проверка

- Юнит-тесты формулы проверяют границы до и от 3000, невалидные значения, округление и CNY/USD.
- Контрактные тесты HTML проверяют один `h1`, связанные label/input, `output`, кнопки валют с `aria-pressed`, JSON-курсы и `dialog`.
- Контрактные тесты JS проверяют GSAP, `prefers-reduced-motion`, ожидание `platejka:ready`, пересчёт и открытие модалки.
- Выполняются `npm test`, production build и HTML-валидация, если валидатор доступен.
- Desktop и mobile сверяются визуально с соответствующими Figma nodes; отдельно проверяются промежуточная ширина, клавиатурная навигация и состояние reduced motion.

## Критерии готовности

- Hero визуально соответствует двум макетам без отдельной мобильной копии разметки.
- CNY/USD и сумма 100000 показывают реальный результат сразу после загрузки.
- Изменение суммы и валюты пересчитывает все значения по рабочей формуле.
- CTA открывает доступное модальное окно с актуальной сводкой.
- Анимация видна после прелоадера, не мешает взаимодействию и отключается при reduced motion.
- Контент и курсы имеют явный контракт для последующего вывода из ACF.
- Тесты и сборка проходят без ошибок.
